# Claim-correspondence failure — S9

Read this when a claim-correspondence assertion fails — either the **structural** half (at author time, decidable
on the code without the science run) or the **behavioral** half (at re-wake, read off this run's output). The
per-segment assertions and their worked examples live in **HANDOFF §Phase 5** (nonlinear / assimilation /
structure-preserving); this file is only the failure handling.

A failed claim-correspondence assertion is an **S9 hard-stop surfaced at the WAVE BOUNDARY** — never absorbed as
a reportable negative number. It signals that the method does NOT do what the claim says: the claim's load-bearing
word is not implemented in the code (structural) or not exhibited by the run (behavioral). A real run would only
manufacture a provenance-clean number that tests nothing.

**Do not confuse this with a measured negative outcome.** A genuine negative outcome (routed in
`operational-first.md`) is a *valid* apparatus whose hypothesis is falsified at full scale — an honest
measurement you record (peripheral) or escalate as an S1 (central). An S9 is the *opposite*: the apparatus does
not test the claim at all, so there is no number worth keeping.
Surface it; do not fix-and-rerun your way around it, and do not report it as merely "weak".
