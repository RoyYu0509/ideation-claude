# experiment-writeback — land the audited number, propagate it, or shrink the claim to fit it

> **Where this runs now (2026-06-24).** Write-back no longer happens in `/review` — review is
> **diagnose-only** and edits no paper. This skill is now loaded by the **auto-research loop's
> experiment/draft stage**, which performs the write-back driven by the experiment demand exported in the
> review HANDOFF. The procedure below is unchanged (land + propagate the audited number, or reframe/soften
> when the result is weaker); only the caller and stage moved. References below to "/review's soften / 大修
> machinery" now mean the loop's own claim-reframing / drafting step, not an in-review reviser.

You write a *verified* experiment result into the paper. The number you are given has already cleared
the run-auditor (`run-audit`) and been registered into the audited-values registry (`AUDITED-VALUES.json`).
You work in **mode `consolidate`** — the per-edit number-freeze is LIFTED, so unlike the old blessed-swap
path you may write the audited number AND **propagate it through the whole paper** (the abstract, the
central claim, every dependent statistic) so nothing reads stale next round. The guard is **post-hoc**: an
independent provenance auditor re-derives every number you changed from disk against the registry / run-ledger
and **reverts + surfaces** anything it cannot ground — so a number you cannot ground only loses your work.
You edit `paper/sections/*.tex` (and the master) only; you never touch experiment code, results, or figures.

## Writing the audited number (and propagating it)

The goal hands you the audited swaps, e.g. *"in `results.tex` `26.3` → `24.8` and `63` → `59`."* Apply them
with `Edit`/`MultiEdit`, then carry the change everywhere it implies:

- **Literal numbers** (the common case): edit the `old_string` containing the old literal to a `new_string`
  with the audited new one.
- **Macro placeholders** (`\newcommand{\lsqrTime}{26.3}` / `\def`): the value lives in the macro definition
  line — edit the macro body literal there.
- **Update the provenance comment.** If the section carries a `% Every numeric value below is taken from
  results/…json` note, add the new source file so the trace stays honest.
- **Propagate dependent numbers — but ONLY as bounded derivations of audited values.** If "26.3 s … 63×
  faster" becomes "24.8 s … 59×", recompute the dependent "59×" *from the audited values* and write it; the
  auditor accepts it as a `DERIVED` value (a difference / ratio / percentage / rounding of audited numbers).
  Propagate the same update into the abstract and any claim that quotes it. NEVER invent a dependent number
  with no audited basis — if you cannot derive it from audited values, restore the paper's existing value and
  leave a `% TODO(author): unverified number — <what to check>`. The post-hoc auditor reverts an ungrounded one.

## Figures

Figures are regenerated by re-running `plot_*.py` (done in the run phase), not edited here. The
`\includegraphics{…}` call carries no number, so you only edit the paper if the figure's **filename**
changed or a **caption number** changed (write the audited value, same as any other number).

## A write-back only ever updates an EXISTING number (no new exhibits here)

A consolidate write-back updates a number/cell the paper **already has** — it is the `updates_existing`
(verify) case. A demand that needs a **new** table row, figure curve, or section is `new_exhibit`: that is
authored as a new exhibit in the loop's drafting step, not via this swap path. So you never build a new
float in a write-back swap; if a swap arrives with an empty `old`, treat it as a design error (a verify
item should have a real existing literal) and flag it rather than authoring an exhibit.

## When the result does NOT support the claim (the honest path)

The re-verify step labels the audited result `holds`, `weaker_than_claimed`, `not_distinguishable`,
or `contradicts`. You write the strengthened/updated claim **only on `holds`**. Otherwise the claim
must move to fit the evidence — never the reverse:

- **`weaker_than_claimed`** (e.g. the real speedup is 1.4× where the paper claimed 2.3×): the claim must
  move to fit the real number — but **reframe before you soften**. Retrieve `reframe-result` and try the
  five moves first (`empirical_reframe` / `effect_ratio` / `scope_shrink` / `null_positive`): state the
  measured effect directly, restate it as a ratio / CI bound, narrow the claim to the regime the data fully
  support, or present the smaller result as a real bound — communicating what the data show, more precisely
  and often more positively, never as a hedge. Whatever framing you land on, write the real (smaller) audited
  number everywhere it appears. If no honest reframe improves the claim, **soften/scope** it to what the data
  show — the honest fallback, the same posture `/review`'s escalation performs: weaken the strength, keep it
  honest, cite the new result. Either way, never strengthen-on-fake.
- **`not_distinguishable`** (e.g. coverage 0.971 vs 0.955 single-seed, interval widths tied): the margin is
  within run-to-run noise, so **no advantage is demonstrated — this is a non-result, not a win**. Do not
  narrate the tie/within-noise difference as an advantage on whichever single metric happens to move.
  Retrieve `reframe-result` and reframe the claim to "comparable to" / "on par with" everywhere it appears;
  delete the advantage wording. Keep the experiment and its real numbers (honestly framed); the orchestrator
  has already surfaced the non-result to the report. Per-cell: if only some rows are null, reframe just those.
- **`contradicts`** (the method genuinely doesn't do what was claimed): this is a science decision, not
  a wording one. Do **not** write the old claim. The orchestrator asks the author (soften to what the
  data show / drop the claim / re-open a review round on the new evidence / keep as-is). Whatever the
  author chooses, the real contradicting result and figure stay committed — the evidence is preserved.

The invariant: a claim is written or kept in *strengthened* form only when the audited result
**holds**; every other outcome routes through the loop's own claim-reframing / drafting step (the downstream owner of revision). Never
let a small, within-noise, or opposite real number sit under an unchanged strong claim.

## When the result is STRONGER than the claim (do not undersell)

The honest path runs **both ways**. If the audited result is *stronger* than the paper's existing
statement (e.g. the re-measured relative effect is **larger**, or a matched/controlled comparison that
removes a confound makes the gap *wider*), do **not** write a number or framing weaker than the evidence,
and do **not** retroactively label the paper's earned result as a looser "unmatched/uncontrolled"
measurement. If a genuinely more-conservative framing is warranted, it must be raised explicitly as a
*contradiction* with the already-audited stronger result for the author to resolve — never silently
swapped in. When both a relative and an absolute form of the same result are written back, they must be
**mutually consistent** (e.g. the "%" and the raw values compute to each other).

## Commit discipline

Edit/MultiEdit only (never `Write` on the manuscript). Commit only the paper files you touched
(`git add -- <files>`, never `git add -A`). One write-back commit per experiment item, named with the
work_id, so each landed result is independently reviewable and revertible.
