# reframe-result — reframe-first, soften only as the honest fallback

A claim looks stronger than its evidence. The reflex is to **hedge or soften** it. That reflex is
usually wrong: softening throws away real signal and adds the defensive register that reads as AI.
**First look for a more honest, more correct FRAMING** that communicates what the data actually show,
more precisely and often more positively. Soften only when no honest reframe exists.

This is the rescue instinct from `/review`, made reusable so any writer (polish-prose, a section
reviser) can reach it the moment a borderline claim appears — not only after escalation.

## The discipline (order is the point)

1. **Reframe first.** Run the checklist below and try the five moves. A legitimate reframe beats a soften.
2. **Soften is the fallback, not the default.** Only when no honest reframe improves the claim do you
   weaken it — and a soften is still an *honest* edit (scope it to the data, cite the real number).
3. **NEVER fabricate.** A reframe is a different *framing of the same evidence*, never new evidence.
4. **Cite specific on-disk evidence.** Every reframe must name the concrete basis — a CI bound, an
   effect ratio, an actual value from a results file or the audited-values registry. No basis → no reframe.
5. **No new hedge.** The reframe must be a *concrete empirical statement*, not a softer shell. Do not
   trade a clean overclaim for `may`/`could`/`appears to`/`to some extent`/`robustness considerations`.
   That is the defensive/corporate register `house-style` and `check-ai-tells` ban. Reframing that
   produces a hedge has failed. [banned: defensive register] — see `../house-style/references/banned-vocabulary.md`.

## Diagnose before proposing (run this on the claim)

1. Does the CI exclude zero? What are its bounds?
2. Is the sign / direction consistent with the hypothesis?
3. Effect-size ratio (strongest / weakest condition) — is it compelling on its own?
4. Can this item merge with another weak item into a stronger cross-condition pattern?
5. Is the weak / null result itself publishable as a constraint or bound on future claims?
6. What is the minimal scope shrink that makes the claim fully supported by the data?

## The five moves

- **empirical_reframe** — drop the threshold / pass-fail criterion language; state the empirical
  finding directly (e.g. "4.5× topology-dependent separation", not "failed the ≤0.15 criterion").
- **narrative_merge** — combine this weak item with another into one stronger cross-item pattern.
- **null_positive** — the weak / null result is itself valuable: a bound, a constraint, a limit on
  future claims. State it as that, not as a failure.
- **scope_shrink** — narrow the claim to the regime the data *fully* support; keep it at full strength there.
- **effect_ratio** — restate as an effect size / ratio / CI bound rather than a pass/fail on a criterion.

If none of the five yields an honest improvement, the claim is genuinely weak: **soften it to what the
data show** (cite the real number) and move on. That is the correct outcome, not a failure of nerve.

## Freeze still holds

Reframing changes *framing*, never the science. Any number you write must be an audited value or a
bounded derivation of audited values; an independent provenance auditor (`run-audit`) re-derives every
changed number from disk and reverts anything ungrounded. Citations stay frozen — never mint a `\cite`
key or a hand-typed author-year mention to prop up a reframe. A reframe that needs evidence the paper
does not have is not a reframe; scope the claim instead, or escalate it to the author.

**Scope: reframe-result narrows a REAL result only.** If the central claim is DEAD (a negative / falsified
hypothesis), this skill MUST NOT repackage it as a shippable positive — that decision belongs to the owner's
terminal gate. A dead claim is stated honestly as a negative, or the paper is abandoned; never laundered into a
positive by reframing.
